## Decisions
- **2026-10-09** Door + ride built (user asked for it for the pitch, though CLAUDE.md had cut on-bus announcements). Door "sound sonar" (`app/lib/door.ts`, `app/lib/beacon.ts`, door mode in `BusCamera.tsx`): front door = 90% along the bus box toward its front; front = the side the bus moved toward, else RIGHT (UB right-hand traffic: facing the road at a kerbside stop, buses arrive from the left — both photos agree); clock direction from angle (65° phone FOV), steps from box height (bus ≈3 m); beacon panned to the door, faster when facing it; "bus moving, step back" overrides. Ride (`RideGuide.tsx`, `GET /ride`): real stop order from Hamuga, GPS watch (or `?ride=sim`/demo photo = simulated drive), "next stop: X" + "N stops left" at 300 m, "prepare" after the second-to-last stop, "get off now" at 150 m with long vibration, then "arrived". Unknown-to-Hamuga stops count but aren't named. Demo page v2 has door + ride.

Tried OCR in a separate process: 7× slower and wrong reads ("u" 0.2) → reverted. For the pitch: start the server early so warm-up finishes (`pitch_check.py` "voice clips ready"), and wait ~15 s after the plan before opening the camera.
- **2026-10-09** Pitch demo = hosted page (artifact) replaying the real system's outputs (OronTTS clips, Hamuga plan Ч:55, YOLO/PaddleOCR results on the 2 photos, faces blurred) + `server/pitch_check.py` for the live app. Spoken numbers now become digits before matching (`server/numwords.py`: "Дэнжийн мянган"/"манган" → 1000, "арван есдүгээр" → 19) — Whisper writes numbers as words. Real STT miss seen: TTS voice "Дэнжийн 1000 руу" heard as "Энэ чи манган руу" → safely "not found".
- **2026-10-09** User: blind riders can't find on-screen buttons → **every screen is a VoiceOver-style spoken menu** (`app/components/VoiceMenu.tsx`): whole screen = one touch surface; swipe right/left = next/previous option read aloud in Mongolian; one tap = repeat; double tap = choose (before any swipe: the screen's main action, e.g. "say destination"; camera/found screens have none so a stray double tap can't close the camera). Stops at the ends with a double vibration. Keyboard: arrows / Enter / R. Options are also labelled buttons for the phone's own screen reader. First tap plays a gesture tutorial while GPS runs. Menus: ask (say destination / my location / change location / help), where (say where I am / retry GPS / help), planned (open camera / repeat route / other destination / change location / help), camera (repeat route / back / help), found (check again / start over / help). All labels are pre-made clips (`shared/phrases.json`, 36 phrases). iOS: one shared `<audio>` unlocked in the first touch. Fixed while testing: fast swipes skipped (position now in a ref); stopping before the mic came on hung; blocked mic now spoken; "walk 0 m" → "you're at the stop" (<30 m); a /verify timeout is no longer an "unsure" vote (it made the app say "not sure" right before "this is your bus"); "not sure" only after 5 s with no answers.
- **2026-10-09** User: speech didn't suggest a bus. Log showed (1) Whisper splits words ("Сөх Баатарын тал бай" for "Сүхбаатарын талбай") → word search matched "Баатархайрханы 1"; (2) the test link's `?lat=&lon=` (Төв номын сан) made "Сүхбаатарын талбай" "too close". Fixes:
  - **Where am I**: tap Эхлэх → GPS (accepted if ±150 m or better) → shows "Таны байршил: <nearest stop> (N м)"; GPS refreshed on each request. GPS off/denied/imprecise → app asks "Та одоо хаана байна?" and the rider says (or types) a stop/landmark (`POST /locate/voice`, `GET /locate?text=`). "Байршлаа хэлэх" button corrects it any time. `?lat=&lon=` is for testing only.
  - **Matching order**: (1) whole phrase with spaces removed vs stop names, if ≥0.85 and ≥0.05 ahead of the next name; (2) word/stem search; (3) per-word spelling fix (4+ letters); (4) whole phrase ≥0.75. Search results must cover ≥60% of the letters said and have no conflicting word ("Их тойруу" ≠ "Гадна тойруу"; "Төв шуудан" ≠ "Төв номын сан"); 3-letter words match whole words only ("хүн" ≠ "хүнс"). Checked on 17 real phrases: right stop or "not found", no wrong place.
- **2026-10-08** Real photos at Төв номын сан (`app/public/test/tov_nomyn_san_{1,2}.png`, gitignored: bystanders' faces) replace the mock clips; `?image=` shows a photo as the camera. Photo 1 (Hyundai, green LED "Ч55") → "Ч:55 ТАНЫ АВТОБУС" in 6 s in the app; photo 2 (Yutong, half-lit orange LED) → "not sure" for every route, no wrong yes. What it took:
  - **LED "Ч" is drawn like "4"** ("455"): "4"+N counts as Ч:N only if a Ч route N stops here and no route in the whole city is numbered "4"+N (city has no 3-digit routes; 45/47 don't exist). Without bus data: stays unsure.
  - **Only route numbers serving this stop count** for yes *and* no: painted fleet numbers ("13-278", "5-269" read as "269") and phone numbers can no longer say "not your bus".
  - **OCR caps crop height (640), not the long side**: wide bus-side crop shrunk to 640 px read the LED at 0.78 (rejected); at full width 0.95. ~400-550 ms per read on CPU (was ~150 ms).
  - **Sign crop = top 45% of the bus box** (LEDs at 25-30%, fleet numbers at 50%+), up to 1600 px wide.
  - **Other vehicles are blacked out of a bus's sign crop**, incl. weak YOLO hits (bus/car/truck ≥0.2) — photo 2's box covered half of the neighbouring Hyundai's "Ч55" sign. A weak box that's a big piece of the same bus isn't masked.
  - **Numbers count in place names**: "Дэнжийн 1000" was matched to "Дэнжийн 1-р зогсоол" because digits were dropped; now a number must match a stop name's whole number.
  - Half-lit LED (camera shutter vs LED refresh) is unreadable in one frame → idea: combine a few frames of the same track (per-pixel max) to rebuild the sign.
  - **PaddleOCR isn't thread-safe**: with the app keeping 2 `/verify` requests in flight, two FastAPI threads ran it at once → the server hung (a request took >2 min) and twice died with no traceback. Now `ocr.py` reads one sign at a time (lock) and the app sends one request at a time (`MAX_PENDING = 1`). Stress test: 80 requests from 2 concurrent clients, no errors, ~470 ms per read. Photo 1 → "yes" in 5.5 s.
  - oron-tts refuses some number+suffix forms ("1000-ын"): `tts.speakable` falls back to the bare number ("мянга") so the sentence is still spoken.
  - PaddleOCR Cyrillic model (`eslav_PP-OCRv5_mobile_rec`) tested: reads "ИЙН" but still "455", so kept `en`.
- **2026-10-08** Speech input = **server-side Whisper**, not Chrome's `mn-MN` (unmeasured, Google-hosted, varies by browser; useless anyway when our server is down). Model `Blgn94/whisper-large-v3-turbo-mn-lora` (Apache 2.0, CER ~11%, fastest accurate option; `STT_MODEL=BuzzASR/mongolian` is more accurate but 2× bigger). **float32** on MPS: float16 and bfloat16+SDPA randomly output "!!!!" (measured). One request: `POST /plan/voice` (WAV + GPS) → heard text + bus. User wants speed: no "did you say X?" step; the spoken plan names the stop, so a mishearing is audible. Measured voice→bus ≈1.2 s (GPU idle), ≈2 s while a TTS clip runs; + ~0.7 s end-of-speech detection in the app.
- **2026-10-08** All GPU work goes through one priority queue (`server/gpu.py`): speech in > live TTS > background clips. Running two MPS models at once corrupted Whisper output (invalid token ids) and slowed both ~50×. A running TTS clip can't be interrupted, so during the one-time route-clip warm-up (first ~1 h) a request can wait up to ~16 s.
- **2026-10-08** Where to get off: the stop the rider named (all its sides of the street, same name within 1 km) — **always tried first**, even if a neighbour is fewer stops. A stop within 500 m is used only when no direct bus reaches the named one, and the speech then says "<place> тэндээс ойрхон". (Bug fixed: neighbours were mixed in with "fewest stops wins", so riders were told to get off one stop early.) "Right direction" = boarding stop comes before the stop in Hamuga's ordered stop list for that route. `PlanResponse.destination` = what was matched; app shows "Сонссон: …" + "Очих: …"; server logs `voice: heard … -> …`.
- **2026-10-08** Destination = the one place whose full name sounds most like what was heard (+ all stops within 500 m of it). A shared word never picks a second place across town (misheard "Улсын их дэлгүүр" once matched the airport via "улсын"). Fuzzy fallbacks: per-word (`difflib` ≥0.75) then whole phrase (≥0.75; measured near-misses 0.88–0.92, garbage ≤0.54) → else "not found, say it again".
